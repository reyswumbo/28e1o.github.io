1. PRASYARAT & PATH PENTING DI VPS INI
------------------------------------------------------------------------
- Python   : /usr/local/bin/python3.11
- yt-dlp   : /usr/local/bin/yt-dlp   (file zipapp, TANPA ekstensi)
- ffmpeg   : /usr/bin/ffmpeg          (untuk merge video+audio)
- curl     : /usr/bin/curl
- curl_cffi (python): sudah ada (0.16.3) -> dipakai untuk request
  yang butuh menyerupai browser asli.

PENTING - kenapa yt-dlp harus dipanggil pakai python3.11?

  Kalau dipanggil langsung:
      /usr/local/bin/yt-dlp --version
  => Error:
      ImportError: You are using an unsupported version of Python.
      Only Python versions 3.10 and above are supported by yt-dlp

  Karena shebang file itu nunjuk ke python3 versi lama.
  Jadi SELALU jalankan begitu:

      /usr/local/bin/python3.11 /usr/local/bin/yt-dlp ...

  Biar ringkas, bikin alias:
      alias ytdlp='/usr/local/bin/python3.11 /usr/local/bin/yt-dlp'
  (taruh di ~/.bashrc kalau mau permanen: echo "alias ytdlp='/usr/local/bin/python3.11 /usr/local/bin/yt-dlp'" >> ~/.bashrc)

------------------------------------------------------------------------
2. PERINTAH DASAR yt-dlp (yang sering dipakai)
------------------------------------------------------------------------
- Cek daftar format/kualitas (tidak mengunduh):
      ytdlp -F "<URL>"

- Unduh kualitas terbaik + gabung jadi 1 mp4:
      ytdlp -f "bv*+ba/b" --merge-output-format mp4 "<URL>"

- Pilih resolusi tertentu (contoh 720p):
      ytdlp -f "bv*[height<=720]+ba/b[height<=720]" --merge-output-format mp4 "<URL>"

- Tentukan nama file pakai judul:
      ytdlp -o "%(title)s [%(id)s].%(ext)s" "<URL>"

- Pakai cookies (kalau butuh login / kena blokir):
      ytdlp --cookies cookies.txt "<URL>"

- Unduh pakai metadata + thumbnail:
      ytdlp --write-thumbnail --write-info-json "<URL>"

Arti singkatan format:
  bv* = video terbaik, ba = audio terbaik, b = format gabungan (muxed)
  Tanda "+" = digabung pakai ffmpeg, "/" = alternatif/cadangan.

4. WEIBO BIASA (stream ada di weibo/video.weibo)
------------------------------------------------------------------------
Jenis URL yang didukung yt-dlp:
  - Halaman status : https://m.weibo.cn/detail/<MID>
  - Halaman status : https://m.weibo.cn/status/<MID>
  - Profil user    : https://weibo.com/u/<UID>
  - Video weibo    : https://video.weibo.com/show?fid=...
  - Video tv       : https://weibo.com/tv/show/<VIDEO_ID>

a) Unduh 1 video weibo:

      ytdlp -f "bv*+ba/b" --merge-output-format mp4 \
          -o "%(title)s [%(id)s].%(ext)s" \
          "https://m.weibo.cn/detail/5012345678901234"

b) Kalau muncul halaman "Sina Visitor System" / butuh login,
   WAJIB pakai cookies dari browser (lihat Bab 6):

      ytdlp --cookies cookies-weibo.txt \
          -o "%(title)s [%(id)s].%(ext)s" \
          "https://m.weibo.cn/detail/5012345678901234"

c) Unduh semua video dari 1 akun (feed user):

      ytdlp --cookies cookies-weibo.txt \
          -f "bv*+ba/b" --merge-output-format mp4 \
          "https://weibo.com/u/7420472445"

d) Cuma mau tahu videonya ada di mana / URL langsungnya:
      ytdlp -g "https://m.weibo.cn/detail/<MID>"

e) PILIH RESOLUSI (720p/1080p) TANPA COOKIE  <-- PENTING
   Catatan: "media_info.stream_url" cuma kasih versi HD (~480p).
   Varian resolusi lain ada di "page_info.urls" (kunci: mp4_720p_mp4,
   mp4_1080p_mp4, mp4_hd_mp4, mp4_ld_mp4). Ambil langsung, contoh:

     MID=5354252771787720
     curl -s "https://m.weibo.cn/statuses/show?id=$MID" \
       -H "user-agent: Mozilla/5.0 (iPhone; CPU iPhone OS 16_0 like Mac OS X)" \
       -H "X-Requested-With: XMLHttpRequest" -H "Accept: application/json" \
       -H "Referer: https://m.weibo.cn/detail/$MID" \
     | /usr/local/bin/python3.11 -c "
     import sys,json
     u=(json.load(sys.stdin).get('data',{}).get('page_info') or {}).get('urls') or {}
     print('720p  ->', u.get('mp4_720p_mp4'))
     print('1080p ->', u.get('mp4_1080p_mp4'))
     print('hd    ->', u.get('mp4_hd_mp4'))"

   lalu unduh URL 720p-nya:
     curl -s -o out_720p.mp4 -H "user-agent: Mozilla/5.0" "<URL_mp4_720p>"
     ffprobe -v error -select_streams v:0 -show_entries stream=width,height -of csv=p=0 out_720p.mp4

   Contoh nyata (sudah diuji dari VPS ini): MID 5354252771787720
   -> mp4_720p_mp4 template 1716x720 (720p, benar-benar HD), file ~7.3 MB.
   Kalau kunci 1080p tidak ada, berarti video itu memang max 720p.

Konversi MID <-> UID/BID (kalau punya link weibo.com/<uid>/<bid>):
  yt-dlp juga bisa langsung terima URL weibo.com/<uid>/<bid> itu.

5. WEIBO YANG DI-HOST TENCENT (v.qq.com)  <-- KASUS KHUSUS
------------------------------------------------------------------------
Gejala: url weibo ini normal, tapi yt-dlp gagal dengan pesan:

      ERROR: [Weibo] ...: There is no video for this status
      atau "No video formats found!"

Sebab: videonya bukan disimpan di server Weibo, tapi di TENcent Video
(v.qq.com). Weibo hanya menyimpan link pengalih berbentuk:

      ...redirect_tencent_video.json?vid=XXXXXXXXXXXXXXXX

Jadi kita harus:
  (1) ambil "vid" dari data status weibo,
  (2) download dari v.qq.com/x/page/<VID>.html (didukung yt-dlp
      lewat extractor "vqq:video").

--- 5A. Ambil "vid" dari JSON status weibo ---------------------------
TRIK PENTING: endpoint mobile HARUS dikirimi header
    X-Requested-With: XMLHttpRequest
tanpa header itu, server balas halaman HTML "Sina Visitor System"
(bukan JSON). Dengan header itu, TIDAK PERLU COOKIE sama sekali.
(Cara ini sudah diuji di VPS ini dan berhasil.)

Ganti <MID> dengan id status (angka di URL m.weibo.cn/detail/<MID>):

      MID=5354343534430126
      curl -s "https://m.weibo.cn/statuses/show?id=$MID" \
        -H "user-agent: Mozilla/5.0 (iPhone; CPU iPhone OS 16_0 like Mac OS X) AppleWebKit/605.1.15 Mobile/15E148 Safari/604.1" \
        -H "X-Requested-With: XMLHttpRequest" \
        -H "Accept: application/json, text/plain, */*" \
        -H "Referer: https://m.weibo.cn/detail/$MID" \
      | /usr/local/bin/python3.11 -c "
import sys,json,re,urllib.parse
d=json.load(sys.stdin).get('data',{})
pi=d.get('page_info') or {}
mi=pi.get('media_info') or {}
u=mi.get('stream_url') or ''
vid=re.search(r'vid=([^&]+)',u)
raw=urllib.parse.unquote(json.dumps(d,ensure_ascii=False))
qq=(re.search(r'https?://v\.qq\.com/x/(?:cover|page)/[0-9a-zA-Z]+/[0-9a-zA-Z]+\.html',raw)
    or re.search(r'https?://v\.qq\.com/x/page/[0-9a-zA-Z]+\.html',raw))
print('VID =', vid.group(1) if vid else '-')
print('QQ  =', qq.group(0) if qq else '-')
print('URL =', u)
"

Contoh keluaran (nyata dari VPS ini, MID 5354343534430126):
      VID = h4102f0x9ro
      QQ  = https://v.qq.com/x/cover/mzc00200w9z1axf/h4102f0x9ro.html
      URL = https://multimedia.api.weibo.com/2/multimedia/redirect_tencent_video.json?vid=h4102f0x9ro

PENTING: pakai URL "QQ" yang muncul itu (bentuk /x/cover/<series>/<vid>.html),
JANGAN mengarang /x/page/<vid>.html. URL cover membawa parameter "series id"
(cid) yang dibutuhkan API Tencent. Kalau "QQ = -", coba cari manual:
      curl -s "https://m.weibo.cn/detail/$MID" ... (lihat field page_info.page_url)

CATATAN: kalau "VID = TIDAK ADA", berarti itu video weibo biasa
(bukan tencent) -> cukup pakai perintah Bab 4.

Alternatif endpoint desktop (ini butuh cookie login):
      curl -s "https://weibo.com/ajax/statuses/show?id=<MID>" \
        -H "user-agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/125.0" \
        -H "cookie: <COOKIE>"

--- 5B. Download dari v.qq.com ---------------------------------------
Setelah dapat URL "QQ" di atas:

      ytdlp -f "bv*+ba/b" --merge-output-format mp4 \
          -o "%(title)s.%(ext)s" \
          "https://v.qq.com/x/cover/<SERIES>/<VID>.html"

Kalau videonya berbayar/regional, tambahkan cookies tencent:
      ytdlp --cookies cookies-qq.txt "https://v.qq.com/x/cover/<SERIES>/<VID>.html"

PENTING (sudah diuji): kalau dari IP di LUAR CHINA (termasuk VPS Tencent
Cloud Singapore ini), Tencent sering balas:
    code "69.2"  msg "这个视频被外星人劫走，暂时看不了了~"
(makna: konten tidak tersedia di region ini)  ATAU
    KeyError('fvkey')  (stream terkunci DRM / butuh login)
Artinya BUKAN salah perintah, tapi GEO-BLOCK / DRM. Solusinya:
    - jalankan dari IP China (VPN/proxy China), ATAU
    - pakai cookies v.qq.com dari akun yang berhak.
Kalau kamu berada di China / pakai VPN China, perintah di atas langsung jalan.

--- 5C. Script otomatis: ambil URL tencent -> langsung unduh ---------
Tidak butuh cookie (pakai trik X-Requested-With). Pemakaian:
      bash weibo_tencent.sh 5354343534430126

Simpan sebagai weibo_tencent.sh:

    #!/usr/bin/env bash
    # Pemakaian: bash weibo_tencent.sh <MID>
    set -e
    MID="$1"
    [ -z "$MID" ] && { echo "Pakai: bash weibo_tencent.sh <MID>"; exit 1; }
    YTDLP='/usr/local/bin/python3.11 /usr/local/bin/yt-dlp'
    QQ=$(curl -s "https://m.weibo.cn/statuses/show?id=${MID}" \
        -H "user-agent: Mozilla/5.0 (iPhone; CPU iPhone OS 16_0 like Mac OS X) AppleWebKit/605.1.15 Mobile/15E148 Safari/604.1" \
        -H "X-Requested-With: XMLHttpRequest" \
        -H "Accept: application/json, text/plain, */*" \
        -H "Referer: https://m.weibo.cn/detail/${MID}" \
      | /usr/local/bin/python3.11 -c "
import sys,json,re,urllib.parse
try: d=json.load(sys.stdin).get('data',{})
except Exception: sys.exit(0)
raw=urllib.parse.unquote(json.dumps(d,ensure_ascii=False))
m=(re.search(r'https?://v\.qq\.com/x/(?:cover|page)/[0-9a-zA-Z]+/[0-9a-zA-Z]+\.html',raw)
   or re.search(r'https?://v\.qq\.com/x/page/[0-9a-zA-Z]+\.html',raw))
print(m.group(0) if m else '')
")
    if [ -z "$QQ" ]; then echo "Tidak ketemu URL Tencent (mungkin video weibo biasa)."; exit 1; fi
    echo "URL = $QQ"
    $YTDLP -f "bv*+ba/b" --merge-output-format mp4 -o "%(title)s.%(ext)s" "$QQ"

Catatan: kalau stream_url TIDAK mengandung "vid=" dan bukan v.qq.com,
berarti itu video Weibo biasa -> cukup pakai perintah Bab 4.

6. CARA BIKIN cookies.txt (BIAR TIDAK KEBLOKIR / BISA KUALITAS TINGGI)
------------------------------------------------------------------------
Cara termudah: ekstensi browser "Get cookies.txt LOCALLY" (Chrome/
Firefox). Buka situsnya saat sudah login, lalu Export -> simpan
cookies.txt (format Netscape). Taruh di VPS, mis. /root/cookies-bili.txt.

Alternatif lewat terminal (dari browser yang sama):
  - Chrome/Chromium: ekstensi di atas, atau devtools -> Network ->
    klik request -> Copy as cURL -> lihat header "cookie: ...".
  - Format Netscape (teks) isinya kira-kira:
        # Netscape HTTP Cookie File
        .bilibili.com	TRUE	/	FALSE	0	SESSDATA	xxxxx
        .bilibili.com	TRUE	/	FALSE	0	bili_jct	xxxxx
        .weibo.com	TRUE	/	FALSE	0	SUB	xxxxx

Kalau kamu cuma punya cookie bentuk header ("SESSDATA=xxx; bili_jct=yyy"),
ubah dulu ke format Netscape. Contoh cepat pakai python3.11:

    /usr/local/bin/python3.11 - <<'PY'
    raw="SESSDATA=xxx; bili_jct=yyy"   # <- isi cookie kamu (header)
    domain=".bilibili.com"              # ganti domain sesuai situs
    out=["# Netscape HTTP Cookie File"]
    for p in raw.split(";"):
        p=p.strip()
        if not p or "=" not in p: continue
        k,v=p.split("=",1)
        out.append(f"{domain}\tTRUE\t/\tFALSE\t0\t{k.strip()}\t{v.strip()}")
    open("cookies.txt","w").write("\n".join(out)+"\n")
    print("cookies.txt dibuat")
    PY

Cookie penting:
  - Bilibili : SESSDATA  (dan bili_jct)
  - Weibo    : SUB (dan SUBP)
  - Tencent  : dari v.qq.com

7. ERROR UMUM & SOLUSINYA
------------------------------------------------------------------------
1) "unsupported version of Python" saat manggil yt-dlp
   -> jangan panggil /usr/local/bin/yt-dlp langsung; pakai
      /usr/local/bin/python3.11 /usr/local/bin/yt-dlp ...

2) Bilibili: HTTP Error 412: Precondition Failed
   -> IP diblokir risk-control. Solusi (urut): pakai --cookies,
      ganti jaringan/IP, atau proxy residensial. Perintahnya tetap benar.

3) Weibo: halaman "Sina Visitor System" / JSON kosong
   -> Anda lupa header X-Requested-With: XMLHttpRequest (lihat Bab 5A).
      Kalau tetap gagal, pakai --cookies cookies-weibo.txt, atau IP lain.

4) Weibo: "No video formats found!"
   -> kemungkinan di-host Tencent -> ikuti Bab 5.

4b) Tencent/v.qq.com: code "69.2" "这个视频被外星人劫走，暂时看不了了~"
    atau KeyError('fvkey')
   -> GEO-BLOCK / DRM: VPS ini di luar China (Tencent Cloud Singapore),
      jadi Tencent menolak. Ini BUKAN salah perintah. Solusi: jalankan
      dari IP China (VPN/proxy), atau pakai cookies v.qq.com akun
      yang berhak. Kualitas tertinggi biasanya juga butuh login/VIP.

5) Gabungan video+audio gagal / hasil cuma suara atau cuma gambar
   -> pastikan ffmpeg ada (which ffmpeg) dan pakai
      -f "bv*+ba/b" --merge-output-format mp4

6) Unduhan lambat/putus
   -> tambah: --retries 5 --fragment-retries 5
   -> atau pakai aria2c kalau ada: --downloader aria2c

7) Nama file aneh / terlalu panjang
   -> pakai -o "%(id)s.%(ext)s" atau --restrict-filenames
